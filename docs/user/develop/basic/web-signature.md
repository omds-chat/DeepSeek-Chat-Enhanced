# 网页签名与运行时校验

本文说明 DeepSeek-Chat-Enhanced 网页产物如何逐文件签名,以及页面在运行时如何静默校验签名。内容与 `scripts/sign-web.mjs`、`rspack.config.ts` 与 `src/services/integrity/` 的当前实现一致,未实现的能力不写入本文。

## 机制概览

| 环节 | 位置 | 说明 |
|:---:|:---:|:---:|
| 签名 | `scripts/sign-web.mjs` | 产物生成后,对每个代码类文件单独签名 |
| 清单 | `dist/web_sign.json` | 随产物分发,记录每个文件的签名 |
| 公钥注入 | `rspack.config.ts` | 构建时由私钥推导公钥,注入 `__WEB_PUBLIC_KEY__` |
| 运行时校验 | `src/services/integrity/` | 页面挂载后静默并行校验,失败只提示警告 |

## 签名范围

| 文件类型 | 是否签名 | 说明 |
|:---:|:---:|:---:|
| `.html` | 是 | 页面入口 |
| `.js` | 是 | 主包与异步分包 |
| `.css` | 是 | 主样式与异步样式 |
| 图片、字体 | 否 | 二进制资源 |
| `LICENSE` 等文本 | 否 | 非代码文件 |

`web_sign.json` 自身不在签名范围内,它只记录其他文件的签名。

## 算法与清单格式

签名采用 hash-then-sign:先对文件字节做 SHA-512 摘要,再用 Ed25519 私钥对摘要签名,签名值以 base64 编码。

清单结构:

```json
{
  "sign": [
    { "value": "<base64 签名>", "for": "static/js/main.abcdef12.js", "signer": "dsc" }
  ]
}
```

| 字段 | 说明 |
|:---:|:---:|
| `value` | 文件字节 SHA-512 摘要的 Ed25519 签名,base64 编码 |
| `for` | 相对 `dist` 根目录的路径,使用正斜杠 |
| `signer` | 固定为 `dsc`,表示由该产品本体签发 |

## 构建期签名

签名脚本读取环境变量 `WEB_PRIVATE_KEY`,该变量存放 PKCS#8 PEM 格式的 Ed25519 私钥。脚本遍历 `dist` 下全部 `.html`、`.js`、`.css` 文件,逐个生成签名条目并写出 `dist/web_sign.json`;签名过程只读取文件字节,不修改被签名的文件。

| 情形 | 行为 |
|:---:|:---:|
| 未设置 `WEB_PRIVATE_KEY` | 脚本以非零退出码结束并给出提示,不产出签名文件 |
| 私钥不是 Ed25519 | 脚本以非零退出码结束并提示算法不符 |
| `dist` 不存在 | 脚本报错并提示先执行构建 |
| `dist` 下没有可签名文件 | 脚本报错,避免产出空清单 |

本地完整复现:

```
WEB_PRIVATE_KEY="$(cat secret)" pnpm build
WEB_PRIVATE_KEY="$(cat secret)" pnpm sign
```

构建与签名必须使用同一把私钥:构建时把公钥注入产物,签名时用私钥签发清单,两者不配对时运行时校验必然失败。

## 构建时注入公钥

`rspack.config.ts` 通过 `DefinePlugin` 定义全局常量 `__WEB_PUBLIC_KEY__`,值为由 `WEB_PRIVATE_KEY` 推导出的 SPKI PEM 公钥字符串。

| 情形 | `__WEB_PUBLIC_KEY__` |
|:---:|:---:|
| 设置了 `WEB_PRIVATE_KEY` | 推导得到的公钥 PEM |
| 未设置 `WEB_PRIVATE_KEY` | 空串,构建照常完成,运行时跳过校验 |

环境变量 `WEB_PUBLIC_KEY` 不参与注入:公钥一律以私钥推导结果为准,避免两者不一致。

## 运行时校验

页面挂载后调用 `verifyWebIntegrity()`,该校验异步执行,不阻塞渲染,且只执行一次。

| 步骤 | 行为 |
|:---:|:---:|
| 公钥为空 | 直接返回,本地开发与未签名的构建不发起任何请求 |
| 拉取 `web_sign.json` | 相对页面地址请求;失败时静默返回 |
| 清单结构不符 | 静默返回 |
| 逐文件校验 | 并发上限 6,拉取文件字节后比对 SHA-512 摘要并验证 Ed25519 签名 |
| 全部通过 | 完全静默 |
| 存在失败 | 汇总失败数量与前几个文件名,以一条警告轻提示告知用户 |

校验失败不阻断服务、不重试、不弹窗:页面照常运行,提示内容说明产物与签名清单不一致,建议刷新或重新下载。

Ed25519 验签使用 `@noble/ed25519`,哈希路径接到 WebCrypto 的 SHA-512,不额外引入哈希实现。这样既不依赖浏览器对 WebCrypto Ed25519 的支持程度,也避免自己维护密码学实现。

## 发布流水线

`.github/workflows/pages.yml` 在构建步骤注入 `secrets.WEB_PRIVATE_KEY`,并在构建之后、上传产物之前执行 `pnpm sign`。密钥缺失时签名步骤直接失败并给出明确错误,避免发布未签名的产物。

## 换行符

签名基于文件字节,换行符变化会让签名失效。仓库统一 LF,`.gitattributes` 的第一条规则为 `* text=auto eol=lf`。

## 排错

| 现象 | 常见原因 |
|:---:|:---:|
| 产物里 `__WEB_PUBLIC_KEY__` 为空 | 构建时未设置 `WEB_PRIVATE_KEY` |
| `pnpm sign` 报缺少环境变量 | 未设置 `WEB_PRIVATE_KEY` |
| 页面提示签名校验未通过 | 产物在签名后被改动,或构建与签名使用了不同的密钥 |
| 校验始终静默 | 产物未带签名清单,或运行时公钥为空 |
