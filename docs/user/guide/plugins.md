# 插件使用指南

本文面向普通用户,说明如何在 dsc 中查看、安装与管理插件。

## 插件能做什么

dsc 插件在浏览器里扩展应用已有的能力,可用的能力包括:

| 能力 | 对用户的意义 |
|:---:|:---:|
| 读取会话列表与会话内容 | 插件可以读取会话标题、消息文本与附件描述 |
| 重命名会话 | 插件可以按规则整理会话标题 |
| 订阅会话切换事件 | 插件可以在你切换会话时做出响应 |
| 显示宿主提示 | 插件可以弹出应用统一的提示条 |
| 保存自己的本地设置 | 插件可以在浏览器本地保存自己的配置 |

插件不能直接改动页面布局或添加按钮;插件产生的可见提示统一走应用已有的提示条与文案。

## 在哪里打开插件面板

- 侧边栏底部的「插件」按钮。
- 侧边栏收起后,入口是左上角按钮组里的插件图标。

插件页会替换主区域的对话界面,再次点击「插件」按钮、点击任意会话或点「开启新对话」即可回到对话。插件页由标题、分段标签页与底部安装栏组成:

| 区域 | 内容 |
|:---:|:---:|
| 已安装 | 插件的名称、版本、状态、来源与操作 |
| 插件市场 | 从插件索引读取的插件列表,可刷新索引并直接安装 |
| 从地址安装 | 「已安装」标签页底部的地址输入框与「安装」按钮 |
| 从本地安装 | 地址输入框旁的「从本地安装」按钮,选择离线包后安装 |

## 如何从地址安装插件

1. 打开插件面板。
2. 在「从地址安装」的输入框中粘贴插件产物地址。地址需以 `https://` 开头,其余协议与主机一律拒绝,输入框下会提示地址无效。
3. 点击「安装」。安装成功后提示「插件已安装」,插件随即自动启用。
4. 在「已安装」中确认状态为「运行中」。

安装所需的插件信息来自产物自带的清单,你不需要另外填写。

若安装提示插件产物地址请求不到,应用会再查各插件来源发布的已移除插件清单:

| 情形 | 提示 |
|:---:|:---:|
| 链接指向已被来源移除的插件 | 该插件已不再受该插件来源支持,请关注其他来源 |
| 清单里没有这个插件 | 找不到这个插件,请检查链接是否正确 |
| 清单全部无法访问 | 沿用原有安装失败提示,不作判断 |

已移除的情形不会删除任何本地安装记录与插件数据,是否保留由你自行决定。

安装记录保存在浏览器本地,下次打开页面时自动恢复;若产物地址已经失效,该插件显示为「启动失败」,不影响其他插件与页面使用。

## 如何从本地安装插件

1. 打开插件面板。
2. 点击「从本地安装」,选择一个离线包文件。选择框一次只接受一个文件,只接受 `.zip` 与 `.tgz`。
3. 在弹出的确认对话框中核对插件名称、版本、作者、许可证、签名状态与是否已安装。
4. 点击「确认安装」;成功后提示「插件已安装」,插件随即自动启用。

离线包有两种格式:

| 格式 | 产物位置 | 说明 |
|:---:|:---:|:---:|
| zip | 包根目录 | 根目录直接放 `meta.json` 与 `plugin.js`,可选作者签名 `plugin.js.author.sig` 与 `author_pub.pem` |
| npm 包(`.tgz`) | `package/dist/` | 只安装该目录下的产物,`package/` 下的其他内容被忽略 |

安装前会做以下检查,任何一项不通过都在确认对话框内说明原因,不会弹出系统对话框:

| 检查 | 不通过时的提示 |
|:---:|:---:|
| 包内必须有 `meta.json` 与 `plugin.js` | 提示缺少哪个文件 |
| `meta.json` 可解析,`name`、`version`、`author` 非空,`version` 为三段数字 | 提示清单内容不合规 |
| 包内同时有 `plugin.js.author.sig` 与 `author_pub.pem` 时按约定验签 | 提示签名校验未通过,仍可确认安装 |
| 插件代码不超过 1 MB | 提示超过上限,请精简产物后重新打包 |

签名与风险:

- 包内带签名材料时,安装前与每次打开页面时都会对插件代码验签;校验不通过时会提示你,但不会阻止安装或启动,请自行判断是否继续使用。
- 包内没有签名材料时仍然可以安装,但确认对话框会标明「未提供签名」,该插件在「已安装」中显示为「未校验」。未校验的插件无法确认代码是否被改动过。
- 离线包不经过插件市场,也没有来源可信度校验。只安装自己打包或从可信作者处获得的离线包。
- 同 id 的插件已安装时不会覆盖,需要先在「已安装」中卸载。
- 卸载不会删除插件的本地数据;重新安装同一 id 的插件仍能读到之前写入的数据。

## 插件的签名状态

插件安装前与每次打开页面时都会校验插件代码的签名,结果分为三种:

| 结果 | 界面表现 |
|:---:|:---:|
| 通过 | 「已校验」 |
| 未提供签名 | 「未校验」,提示自行判断 |
| 校验失败 | 「校验失败」并提示,插件仍然安装与启动 |

签名只能证明文件与签名者签署时一致,不能证明签名者可信;来源是否可信看「插件市场」里的「可信」「不可信」「信任未知」标识。签名体系与校验流程见 [信任链与 PKI 签名](../develop/basic/trust-chain.md) 。

来源结论与签名状态相互独立,同样显示在插件名下方: 证书链与验签都通过为「来源已确认」,未在官方清单登记时另附「未在官方清单登记」的中性标注;证书链不通过、证书已被吊销、证书文件缺失与验签不通过分别显示「来源证书校验未通过」「来源证书已被吊销」「来源证书缺失」「来源校验未通过」;完全没有来源信息的记录显示「来源未确认」。

## 如何启用、停用与卸载

「已安装」列表的操作列固定有三个按钮,另有按情形出现的「可更新」与「重新安装」:

| 按钮 | 作用 |
|:---:|:---:|
| 启用 / 停用 | 停用会立即撤销插件的能力与事件订阅;启用会重新执行插件的启动逻辑 |
| 查看日志 | 查看该插件最近写入的日志,最多 100 条,并显示读取时间 |
| 卸载 | 二次确认后移除插件;存在已启用插件依赖它时会被拒绝,需要先停用依赖方 |
| 可更新 | 来源上有更新的版本时出现,二次确认后先卸载旧记录再按新版本安装 |
| 重新安装 | 升级前的安装记录缺少新的校验字段时出现,二次确认后按记录的同一版本重新安装,插件的本地数据会保留 |

升级前的安装记录没有新的校验字段,这类插件在来源结论旁提示「此插件在旧版本安装，重新安装可获得完整的来源确认」,操作列同时给出「重新安装」。

状态列的含义:

| 状态 | 含义 |
|:---:|:---:|
| 运行中 | 已启用并成功激活 |
| 已停用 | 已停用,能力与事件订阅已撤销 |
| 启动失败 | 启用时抛错或超时,可查看日志定位 |
| 未启动 | 已登记但未激活 |

## 内置插件与外部插件的区别

| 项 | 内置插件 | 外部插件 |
|:---:|:---:|:---:|
| 来源列显示 | 内置 | 外部;从本地安装的显示「本地」 |
| 安装方式 | 随应用装载 | 从地址安装、从插件市场安装或从本地安装 |
| 卸载 | 不可卸载,按钮禁用并提示内置插件由宿主装载 | 可卸载 |
| 读取外部网页 | 可以 | 不可以 |
| 默认状态 | 首次出现时默认启用 | 安装后立即启用,之后按你的选择恢复 |

内置插件是 `dsc-market`,它负责读取插件索引,为「插件市场」标签页提供列表。

外部插件不能读取任意外部网页:只有内置插件可以发起外网请求,以免插件把页面数据发往任意地址。内置插件的联网请求同样受限,只允许 `https` 请求且不携带 Cookie。具体限制见 [dsc 插件开发规范](../develop/basic/plugin-develop-spec.md) 。

## 安全提示

- 插件是运行在当前页面里的脚本,与页面同源。能力层限制了插件通过引擎接口能拿到什么,但插件代码仍可能直接读取页面可访问的数据,包括浏览器里保存的 API Key 与会话内容。
- 只安装你信任来源的插件。安装前先核对产物地址的域名与作者,不确定就不要安装。
- 插件市场收录的是社区作品,收录不等于安全审查通过。
- 从本地安装的插件不经过市场与来源校验。签名只能证明包内的插件代码与签名者签署时一致,不能证明签名者可信。
- 发现异常行为时立即卸载插件并更换 API Key;已经泄露的会话内容无法撤回。
- 卸载前可以先点「查看日志」,确认插件的实际行为。

## 卸载与插件的本地数据

插件自己的数据保存在浏览器本地,单个插件的总量上限 64KB。

| 操作 | 对插件数据的影响 |
|:---:|:---:|
| 停用 | 保留 |
| 卸载 | 保留。卸载只移除插件本身与安装记录,本地数据留在浏览器里 |
| 设置的数据管理中的清理 | 删除指定插件或全部插件的本地数据 |
| 清除站点数据或浏览器存储 | 删除 |

卸载确认框会说明本地数据不会被删除,卸载后界面提示可在设置的数据管理中清理。重新安装同一 id 的插件时,它仍能读到上一次写入的数据。
